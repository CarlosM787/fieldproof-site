## Keyboard, screen reader, motion, layout shift

Checked with Playwright on 3 pages at 390 and 1440 px, reduced motion on (`tools/a11y-keyboard.cjs`, `measurements/prototype-keyboard.json`):

- **Keyboard.** The first Tab lands on "Skip to content", and Enter moves to `#main`. Every stop has a visible 2 px focus ring (46 stops on home, 50 on products, 28 on the detail page). Several cards share the label "View project", so each one carries the product name for screen readers (for example "View project: SitterStack").
- **Screen reader tree** (Playwright ARIA snapshot, stored in the JSON). The skip link comes first, then the landmarks: `navigation "Sites by Carlos Morales Jr."` (the current site is plain text, not a link to itself), then `banner` with `link "Morales Labs, home"` and `navigation "Main"`, then `main`, then `contentinfo`. Each page has one `h1`, and headings run in order. The status is text ("Pilot Prep"); its glyph is `aria-hidden`. The reality facts read as "Website: yes · Use today: no · Buy: no". Map stations are ordered lists under labelled groups. The brand SVG inside the home link is `aria-hidden`, so the link has one clean name.
- **Server-visible text.** Every word is in the HTML. There are 0 script elements apart from JSON-LD, so there is nothing to hydrate and nothing hidden before JS runs.
- **Reduced motion.** There are 0 running animations, and nothing on the page animates in any mode. A `prefers-reduced-motion` guard is still in the CSS for anyone who adds motion later.
- **No layout shift.** CLS measured 0.0000 by a `PerformanceObserver` while scrolling the full page, and 0.000 in Lighthouse. Images carry `width` and `height`, the card image has an `aspect-ratio`, and fonts use `font-display: optional` with preload, so text never swaps after first paint.
- **Responsive images.** Portrait and TalkEstimate card use AVIF → WebP → JPEG/PNG through `<picture>`, with `srcset` and `sizes` (160/320 px portrait; 480/960 px card).
- **Colour.** Light and dark follow `prefers-color-scheme`, and both themes are covered by the axe runs above. Status never relies on colour alone: the shape and the text carry it.

## Known limits

- `font-display: optional` means a visitor on a very slow first visit may see the system font for that page view, with no shift. Repeat views use the cached brand fonts.
- The prototype covers home, products, one detail pattern and the components. Other links go to the live moraleslabs.com pages (Workbench, About, Contact, other studio pages).
- Lab numbers come from a local server: no TLS, no CDN, no third-party tags. Live numbers will be higher. The live moraleslabs.com tag stack is the biggest difference (see AUDIT.md §3).
